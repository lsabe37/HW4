## Devlog

The model view controller pattern is used in this project to separate the Player script with the rest of the scripts. The Player class defines the controller side of this pattern. This class processes the user inputs (whether the space bar is pressed) and fires the jump event when the if statement is true. When the jump event is fired, the VfxManager class, which is subscribed to this event, will be used to play the jump sfx. The player class also uses an OnTriggerEnter2D method to detect when the player collides with a pipe or passes through them (colliding with an invisible collider at the end of the pipe gap). When the player collides with a pipe, the gameOver event is fired. When this occurs, the GameManager, UiManager, and VfxManager class, which are all subscribed to this event, will be used to stop time, show the game over UI, and play the game over sfx. Similarly, when the player passes through a pipe gap, the VfxManager and UiManager scripts, which are subscribed to the getPoint event, are used to play the gainign points sfx and update the score UI. Thus, while the Player class defines the controller side, the VfxManager, UiManager, and GameManager define the view side. By decoupling the system in this way, the Player class does not need references to all three of these classes. The singleton Locator class is used to ensure that the Player class is globally accessable. This enables the view classes to subscribe to the Player class' events, creating the model view controller pattern.
